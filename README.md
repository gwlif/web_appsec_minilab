# Web AppSec Mini Lab

Небольшая локальная лаборатория по безопасности веб-приложений на Python и Flask. Для каждой из трёх категорий есть намеренно уязвимый маршрут, исправленный маршрут и автоматические тесты, демонстрирующие разницу.

> **Внимание:** маршруты `/lab/vulnerable/*` намеренно уязвимы и предназначены исключительно для обучения. Приложение запускается на `127.0.0.1`; не выставляйте его в интернет и не используйте реальные данные.

## Что демонстрирует проект

| Класс проблемы | Уязвимый пример | Исправленный пример | Что проверяют тесты |
|---|---|---|---|
| SQL injection (OWASP A05:2025 — Injection) | `/lab/vulnerable/search?q=...` | `/search?q=...` | Конкатенация SQL позволяет изменить условие; параметризованный запрос трактует ввод как данные. |
| Broken Access Control / IDOR (OWASP A01:2025) | `/lab/vulnerable/notes/<id>` | `/notes/<id>` | Уязвимый маршрут не проверяет владельца; исправленный проверяет `owner_id` текущего пользователя. |
| Reflected XSS (OWASP A05:2025 — Injection) | `/lab/vulnerable/greet?name=...` | `/greet?name=...` | Уязвимый маршрут вставляет ввод прямо в HTML; исправленный использует автоэкранирование Jinja. |
| Базовые настройки защиты | Уязвимые маршруты намеренно без CSP | Защитные HTTP-заголовки на обычных маршрутах | Проверяются CSP, `X-Content-Type-Options`, `X-Frame-Options` и политика `Referrer-Policy`. |

Категории соответствуют OWASP Top 10:2025: <https://owasp.org/Top10/>. Это учебные примеры, не исчерпывающая реализация всего набора требований OWASP.

## Требования

- Python 3.10 или новее.
- Flask 3.x.
- pytest 8.x или 9.x.

## Установка на macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

На Windows активация окружения: `.venv\\Scripts\\activate`.

## Запуск

```bash
python app.py
```

Интерактивная HTML-лаборатория доступна по адресу <http://127.0.0.1:5000/>. На главной странице есть формы для сравнения SQL Injection, IDOR и XSS. CSS и JavaScript интерфейса загружаются отдельными локальными файлами, чтобы работать с настроенной Content-Security-Policy. JSON-статус приложения вынесен отдельно: <http://127.0.0.1:5000/health>. Для остановки нажмите `Ctrl+C`.

Демонстрационные пользователи и пароли:

| Пользователь | Пароль |
|---|---|
| `alice` | `alice-demo-pass` |
| `bob` | `bob-demo-pass` |

Это фиктивные данные лаборатории, не используйте такие пароли в настоящих приложениях. Пароли в SQLite хранятся в виде хешей. При обычном локальном запуске ключ сессии создаётся случайно на старте; для развёртывания даже в тестовом окружении задайте устойчивый секрет через переменную окружения `FLASK_SECRET_KEY`.

## Запуск тестов

```bash
python -m pytest -v
```

Тесты используют временную SQLite-базу и Flask test client — приложение не нужно вручную запускать в отдельном терминале. Отдельный регрессионный тест подтверждает, что `/` возвращает HTML-интерфейс, а не JSON. CI запускает этот набор при `push` и `pull_request`.

## Примеры для ручной проверки

### 1. Сравнение SQL injection

Уязвимый вариант может вернуть обе демо-заметки:

```bash
curl -sG 'http://127.0.0.1:5000/lab/vulnerable/search' \
  --data-urlencode "q=' OR 1=1 --"
```

Исправленный вариант рассматривает ту же строку как обычное значение поиска:

```bash
curl -sG 'http://127.0.0.1:5000/search' \
  --data-urlencode "q=' OR 1=1 --"
```

### 2. Сравнение контроля доступа (IDOR)

Войти как Алиса и сохранить cookie:

```bash
curl -i -c cookies.txt -H 'Content-Type: application/json' \
  -d '{"username":"alice","password":"alice-demo-pass"}' \
  http://127.0.0.1:5000/login
```

Уязвимый маршрут разрешает прочитать заметку Боба с ID `2`:

```bash
curl -i -b cookies.txt http://127.0.0.1:5000/lab/vulnerable/notes/2
```

Исправленный маршрут возвращает `404` для чужой заметки:

```bash
curl -i -b cookies.txt http://127.0.0.1:5000/notes/2
```

После проверки удалите локальный файл `cookies.txt`.

### 3. Сравнение XSS

Откройте в браузере эти адреса и сравните результат. Используйте только локальное приложение:

```text
http://127.0.0.1:5000/lab/vulnerable/greet?name=%3Cscript%3Ealert(1)%3C%2Fscript%3E
http://127.0.0.1:5000/greet?name=%3Cscript%3Ealert(1)%3C%2Fscript%3E
```

Уязвимый endpoint вставляет значение как HTML, а исправленный экранирует его с помощью шаблонизатора.

## Ограничения

- Это учебная демонстрация, не готовый production-шаблон.
- SQL injection и XSS воспроизведены упрощённо на вымышленных данных.
- Уязвимые маршруты существуют намеренно и не должны публиковаться в публичной сети.
- Приложение показывает базовую сессионную аутентификацию, но не реализует полный жизненный цикл управления сессиями, CSRF-токены, восстановление пароля, MFA или полноценную систему ролей.
- Проверка заголовков не заменяет threat modeling, полноценный security review или динамическое тестирование.

## Идеи для дальнейшего развития

1. Добавить CSRF-защиту и тесты для изменяющих состояние операций.
2. Добавить rate limiting и безопасную обработку ошибок аутентификации.
3. Подключить Bandit, pip-audit и coverage в CI.
4. Добавить отчёт по покрытию и матрицу «уязвимость → тест → исправление».
